# 人物批次删除与同步

更新日期：2026-10-25。

此前单张人物任务已有删除入口，但人物批次列表没有删除按钮或整批接口。本次补齐该层，同时处理逐张删除后的空批次。

- 人物批次历史增加「删除批次」和确认提示。运行中的批次须先取消或等待完成。
- `DELETE /api/identity/batches/{id}` 验证持久化批次与所有成员归属后，返回批次编号和完整成员编号列表。重复请求幂等。
- 整批文件使用一个 v3 删除事务提交；最多 16 项、96 个成果文件。移动失败或提交前中断会恢复整批，旧 v1/v2 事务继续兼容。
- 删除状态同时覆盖批次、人物任务、结果卡片、修脸前原图、修脸阶段图片和总历史。确认回执后一次发布浏览器状态，标签页通过同源存储同步；较早的刷新响应不能恢复已删除记录。
- 最后一个成员被逐张删除后，空批次自动隐藏。刷新、重新打开页面和服务重启后，状态来自后端持久回执。
- 人物档案、参考照片、冻结请求及重试来源记录保留。已删批次的中间预览不再提供，界面不再显示结果或重试操作。成果文件仍在本机可恢复暂存区，本次不实现永久清空。

验收采用隔离的 `qa_identity_deletion.py` 合成数据，未删除真实用户作品，也未运行 GPU 生图。浏览器中打开人物批次与另一标签页的总历史，删除两项批次后，批次及成员消失，总历史从 3 张同步为 1 张。刷新、重启和重新打开人物页后状态保持；9 个受保护档案/参考/冻结记录的哈希及未删除成果一致。

验证记录：前端完整 579 项通过，另新增 7 项异常回执校验通过；后端完整 1446 项通过、2 项跳过，另新增进程中断恢复和 16 项/96 文件上限用例通过。新增批次后端用例共 10 项全部通过，TypeScript 检查和生产构建通过。服务重启时测试页的硬件轮询出现一次预期连接拒绝，不属于删除操作错误。

本机 8766 已部署验证过的前端资源与后端；正式页面只读确认删除批次入口可见。启动时一次硬件探测超时返回 503，后续复查 `/api/hardware` 已恢复 200。没有用正式作品执行删除验收。
