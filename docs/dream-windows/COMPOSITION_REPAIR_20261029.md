# 全身构图与局部光照修复（2026-10-29）

## 已修复

- 人物页选择 Cyber 动漫视觉参考、动漫画风、全身构图后，可明确点击“应用全身构图方案”：512×768、30 步、CFG 5、参考强度 0.7、参考区间 0.35–1。先建立画面布局，再加入人物参考。人物档案、参考图、种子、提示词和修脸设置保留；普通场景按钮仍只改提示词，普通模型推荐仍只改四个生成参数。
- 删除动漫预设中重复的质量词，避免预设尾部被文本编码器截断。24 组实际生成的场景提示词经本机两个 CLIP tokenizer 检查：正向最多 72、反向最多 55 个内容 token，均不超过 75。此结果不代表任意用户长提示词都不会被截断。
- 边缘光照协调在量化和裁剪后逐像素检查候选修正；只有减小该像素与不可变原场景之间亮度偏差的改动才保留。防止周围区域的平滑偏移把已匹配或需要反向修正的像素改坏。原编辑蒙版和五官保护边界不变。

## 实际验证与限制

两组固定种子的独立 GPU 对照，仅改变参考开始比例：原设置得到腿部裁切或头肩近景；0.35 开始的两张结果均显示头到脚和园林场景。分辨率、提示词、模型、参考图和其他参数在每组中相同。这是两个样例的构图改善，不能保证所有场景、姿态或人物相似度；小脸细节仍需逐图检查，必要时再做独立精修。

实际保存图片的 CPU 光照对照：局部亮度偏差增加的像素由 620 降为 0，变化像素由 3,839 降为 3,219，最大 RGB 通道变化仍为 2/255；五官保护区和编辑区外 100% 精确保留。该检查是数值约束，不是审美或身份相似度评分。

此全身方案仅向已验证的 Cyber 视觉参考路线开放，不修改 FaceID 默认设置，也不解除 Illustrious Plus 实验路线的禁用状态。模型、私人参考照、原图及样张保留在本机。

## 发布验收

- 浏览器实际选择人物档案、全身构图与古风场景，点击全身方案后提交生成；后端收到全部七项参数，任务完成且结果区显示完整人物和双脚。该样张使用正式场景预设，不只使用对照脚本的短提示词。
- 正式精修 API 执行新版 CPU worker：`immutable-scene-luma-ring-v3`，拒绝 620 个不能改善局部亮度偏差的候选像素，保留 3,219 个修改。原始图片哈希和当前选中版本保持不变。
- 前端完整测试 681 项通过；本次涉及的光照、精修引擎、精修接口及质量诊断后端测试 112 项通过。生产构建通过，浏览器加载新资源。以上后端数量是相关回归范围，不是全后端重跑结果。
- 独立代码审查未发现需修正的问题；426 个既有人物档案、参考和原图文件哈希核对无变化。

使用路径：人物创作 → 选择动漫视觉档案与 Cyber 视觉参考模型 → 全身构图 → 应用所需场景 → 应用全身构图方案 → 生成。先确认构图，再按需做独立精修。

上游行为参考：[Diffusers IP-Adapter 控制说明](https://huggingface.co/docs/diffusers/v0.35.0/using-diffusers/ip_adapter)、[IP-Adapter Face 训练与裁切说明](https://github.com/tencent-ailab/IP-Adapter/wiki/IP%E2%80%90Adapter%E2%80%90Face)。本次参数选择依据上述本机对照结果。
