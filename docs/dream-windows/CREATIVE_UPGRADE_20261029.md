# Dream 创作升级：使用与验收（2026-10-29）

人物独立精修、场景构图与显式参数推荐、受控融合图像实验、显微镜跨运行比较已实现并接入本机浏览器工作台。下列记录本轮实现与本机验收；对应源码提交及 CI 结果请查看 GitHub main 的提交和 Actions 记录。

## 使用方式

1. **独立精修**：从人物结果或历史打开精修工作台，选择已有版本或原图作为输入，调整可用模式、强度 0.15–0.65、提示词和种子，每次提交一轮。完成后选择版本、继续修或回到原图；选择不会覆盖历史主图。失败、取消或无像素变化不会发布伪成功版本。父图删除后，其精修版本也不可访问。
2. **模式选择**：普通 FaceID restore 直接使用修复处理器；视觉重绘/参考脸对齐按当前模型能力开放。edge-lighting 是独立 CPU 边缘/光照候选修正，不加载生成管线，并以不可变原场景作为诊断依据。不存在完美相似度或自动质量优胜判断。
3. **场景与构图**：在生成或人物页选择古风、女帝、公主、科幻及肖像/半身/全身构图。点击场景仅替换正负提示词，可撤销；“应用模型推荐参数”另行显式应用兼容的尺寸、步数、CFG。模型、人物引用、种子及修脸设置不会被静默替换。构图是文字提示，不是骨架或精确姿态约束。
4. **Lab 融合图像**：打开“受控融合图像实验”，设置提示词、seed、steps、CFG、alpha 和尺寸，一次比较 first_only / equal_mean / token_weighted / anchor_residual 四种真实图像。查看来源、权重和计时，可取消运行；重启后可恢复已完成结果。“手机 chunk 预测融合”仍是独立 CPU 导入重放，不等同设备实跑。
5. **显微镜比较**：选择已有运行，在“潜空间”中选“对照运行”，再比较实测指标。仅比较来源、模型、采样配置、形状与采集步覆盖兼容的数据；缺失项不补零。

## 性能与质量边界

普通 restore 通过现有持久传输复用一个兼容处理器，兼容键包含实际资产/配置内容哈希，最多复用 32 次，空闲 TTL 保持 **60 秒**。batch 与 refine 不跨类型复用；fusion、edge-lighting 或其他引擎开始前释放暖 worker。每次报告独立的 sessionReused 与阶段计时。

| 同一输入的观察 | 冷处理器 | 暖处理器 |
| --- | ---: | ---: |
| 端到端耗时 | 79.938 s | 49.296 s |
| load 阶段 | 42.540 s | 1.173 ms |
| sessionReused | false | true |

两次输出哈希相同。测试时另有 **三个 Unity 进程**，且后台 CPU 测试在运行；未取得无争用基准。冷指新 worker/处理器初始化，不代表操作系统或磁盘缓存为空。这只是本次观察，不构成速度保证；内容哈希检查和 CPU 修复仍有开销。

CPU edge-lighting 的实际处理器掩膜诊断显示：保护区与编辑区外像素 **100% 精确保留**；共有 **3,839** 个像素变化，RGB 通道最大绝对变化 **2/255**。改动很轻微，不能据此认定更美观、更相似或质量胜出。通用差异报告缺少掩膜时仍返回 null，不可替代真实保护率。

硬件采样使用有界 3 秒探测、前端 6 秒超时；失败按 3→6→12→30 秒退避，成功复位，隐藏页暂停。失败/过期数据仍显示未知，不被当成当前就绪状态。

## 保留限制与发布状态

- 失败的 Illustrious Plus 实验路线继续受门控并保持禁用，不因其他动漫样张成功而解锁。
- 全身选项和参数应用验证的是 UI/请求行为；不保证最终完整入镜、姿态、手脚或精确人物相似度。
- 像素诊断、同哈希、测试通过和融合算术不证明审美优胜、完美 likeness 或手机/native/device parity。
- 本机验收与 GitHub CI 分开记录；现有 Safe Core CI 检查仓库及安装器，不能替代本轮 Dream 前后端测试、GPU 样张和浏览器验收。

技术约定见 [融合图像契约](TASK4_IMAGE_CONTRACT.md)、[研究路径](TASK4_RESEARCH_20261029.md) 和 [像素诊断/性能方法](../dream-quality-benchmarks.md)。本地验收产物与私有图像保留在本机，不随公开文档发布。
