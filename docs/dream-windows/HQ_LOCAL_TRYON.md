此功能在本机浏览器直接使用。HQ Cloudflare Worker 继续只提供自有 R2 原图和既有授权；不创建云端生成队列，不轮询领取任务，也不上传生成结果。

## 自动识别修图

在[本机试衣页](http://127.0.0.1:8766/?view=hq-tryon)勾选「成片后自动识别修图」（默认开启）。任务在原始生图及可选修脸完成后自行检查，关闭页面不影响执行。在「本机任务与成片 → 自动识别修图」可切换原始成片、修整版、实际改动范围（白色是变过的像素），并下载 SHA-256 验证过的 PNG。旧任务按「检查并修整此图」；已有旧版可按「使用新版重新检查」。取消勾选只影响新任务。重复提交同一底图不会重新生图或重复排队。

- **适用范围**：这是针对配对深度图的局部修整。白模提供轮廓，深度图确认凸出的关节；还需要成片像素及原服装的证据。当前覆盖前景中一对明显放大的膝盖和可单独识别上装的组合。深色团块调用同一底模局部重绘；细线从两侧真实皮肤补齐；对称的同色织物圈用实际皮肤和前景边界修补。确认浅灰硬壳与原深色上装不符时，使用服装原图纹理和服装适配器修整。局部重绘不再施加姿势或人脸控制。
- **正常、遮挡、不确定**：没有足够证据时保留原图，不生成副本。通过检查也不代表整个姿势或所有衣物细节均准确。站姿靴子、整套连体服、普通骨架任务不能据此判定为伪影。
- **本地接口**：`POST /api/hq/jobs` 新增可选 `autoRepairEnabled`；`POST /api/hq/jobs/{id}/body-repair` 检查历史任务；原有任务接口的 `bodyRepair` 单独记录 queued/running/applied/partial/unchanged/rejected/failed。`GET /api/hq/jobs/{id}/body-repair/result` 和 `.../mask` 接受 `?download=1`。原有 `.../result` 始终是生成原图。全部沿用本机来源限制和历史删除状态。
- **存放与排障**：`data/hq/jobs/{id}/body-repair/{版本}/` 下的 manifest、report 记录输入哈希、种子、实际步骤（如使用扩散）、判定区域、变化像素、输出和遮罩哈希；仅有通过检查的版本写 PNG。重绘沿用现有本机人物环境、底模和独占 GPU 队列，不需要额外下载模型。遇到失败先检查 E 盘可用空间、身份运行环境和原任务绑定的文件。修整中断可以在原任务重试，不会重新提交原始生图。
- **回退**：取消自动检查，随时切回或下载原图。回退程序先用 `scripts/stop_dream_web.ps1 -CheckOnly` 核验空闲，再按既有流程停止、切换到上一发布的代码和前端、运行 `scripts/start_dream_web_background.ps1`。保留 `data`、`outputs` 和人物档案。公共 HQ 选材器仍使用白模，未更改云端接口。

本次[真实成片与网页验收记录](HQ_BODY_REPAIR_ACCEPTANCE.md)。

## 使用顺序

打开 `http://127.0.0.1:8766/?view=hq-tryon`。

1. 在「人物来源」选择「图库照片」或「只选本机档案」。前者使用所选 R2 人物原图；后者使用本机 FaceID 档案的参考图和指定人脸，无需人物图库授权。切换来源会清除上一个人物选择，保留服装、姿势及生成参数。
2. 在完整 R2 图库搜索、分类或翻页，按白模预览选择姿势与视角。当前 1,439 个姿势都有对应深度图。
3. 点击「本机生成」后，Dream 按所选白模的编号与原图 SHA-256 查找深度图，将它送入原有 A/B/C 采样流程。缓存缺失时只读取该姿势的 R2 对象。确认区显示所选姿势的控制方式。「套用 A/B/C 定稿参数」可恢复 768×1152、30 步、种子 20261104 和可选修脸强度 0.35。
4. 按需启用原有可选修脸。真人路线沿用身份回贴与细节修复；修脸前底图单独保留，失败需显示原因。
5. 查看底图与结果，再从原有独立精修工作台执行下一轮或回到原图。精修不是自动质量优胜选择。
6. 确认构图与脸形后，可在同一工作台执行“2倍清晰增强”。生成独立版本，不覆盖原图；增强版本可选择、查看与下载，后续精修须回到增强前版本。

尺寸预设支持 512×768、640×960、768×1152 及横版，总像素最多 884736。首次打开时，仍使用旧出厂参数的草稿会采用新的定稿参数。自定义参数、已选人物和正在查看的任务会保留。

2026-11-02 已从正式网页选择人物、SXY-0004 和 P001 仰拍坐姿，生成并下载 768×1152 的 PNG。三路输入各记录到 30 次真实采样调用，浏览器下载与服务端成片的 SHA-256 一致。发布验收实跑的是 A 场景。B 所用另一张深度图通过定稿采样输入校验。这版沿用定稿的服装还原效果，部分鞋履和配件仍有偏差。

完整图库恢复时已逐页核对 1,439 个姿势的编号与 R2 原图哈希，覆盖 26 个分类。此次深度库发布后，1,439 张原始深度图（24,046,098 字节）均已上传到独立前缀并逐张回读核验。每个姿势都校验了对应 R2 白模的原图尺寸。

本机浏览器实测「站立・双手撩发 · 斜侧」在空缓存下取得对应的 R2 深度图。实际输入 ControlNet 的张量与该图一致，完成 30 步采样并下载 768×1152 PNG。原插件的同号取图调用仍返回白模 PNG，发布前后三个代表姿势的白模文件哈希和原 MCP 工具签名逐项一致。此次版本更新位于 Dream 仓库。

预览显示实际文件尺寸，支持适应窗口、100% 原始尺寸和打开原图；200% 只是显示缩放，不增加细节。“2倍清晰增强”是单独运行本地模型，不是浏览器缩放，也不保证恢复缺失的真实细节。

实际三组验收、限制和测试范围见 [2026-11-02 验收记录](HQ_LOCAL_ACCEPTANCE_20261102.md)。当前流程可运行，人物外观与服装细节的视觉总评仍为 PARTIAL。

## 本机服务

沿用桌面 `启用可选修脸.cmd`，或执行：

```powershell
& 'C:/Program Files/PowerShell/7/pwsh.exe' -NoProfile -File E:/Dream/repo/scripts/start_dream_web_background.ps1
```

只在回环地址提供服务。重复启动应复用原服务；不要启动公开 FastAPI、ComfyUI 或任意命令接口。停止前取消未完成任务，等待已有工作进程退出。重新启动后读取本地任务记录，不自动重跑中断的生成。

需要前台运行时可用 `scripts/run_dream_web.ps1 -Port 8766`；在该服务窗口按 Ctrl+C 停止。后台模式先关闭任务提交页面，再运行以下命令。停止脚本会核对本项目服务归属和活动任务，无法确定或仍有任务时拒绝停止，不处理其他项目进程。

```powershell
& 'C:/Program Files/PowerShell/7/pwsh.exe' -NoProfile -File E:/Dream/repo/scripts/stop_dream_web.ps1
```

重新运行启动器并点击页面“刷新图库与任务”即可重连。

## 配置和人物授权

`E:/Dream/data/hq/config.json` 仅由本机后端读取，设置自有 Worker origin、短期会话文件及本地条件配置。人物运行环境、模型和修脸权重沿用 `E:/Dream/data/identity/runtime.json`。原有模型继续从既有安装位置读取；新增配置、缓存和审计放在 E 盘。

可选清晰增强在同一人物运行配置中增加 `upscaleModel`，指向本机已有 `RealESRGAN_x4plus.pth`，其 SHA-256 随每个增强版本记录。使用配置中 `python` 对应环境的 PyTorch、Spandrel 和 Pillow，不依赖网页服务解释器安装推理包。能力检测不加载模型或初始化 GPU；结果短期缓存，配置／模型／解释器文件改变即失效。推理进入现有串行 GPU 队列，用 128 像素分块、32 像素上下文，4倍模型输出降采样为严格2倍；不再加载底模、换脸模型或参考照。未配置或组件缺失时不显示可用增强模式。

人物图库授权复用既有 Cloudflare 登录和私有 R2 会话机制。原始 Bearer 仅保存在当前 Windows 用户和 SYSTEM 可读的本机凭据文件中；R2 只保存会话的 SHA-256 与有效期。浏览器、Git、普通日志和推理进程不接收会话或 Worker 主密钥。无公共免鉴权签发入口。

### 一键授权（2026-11-04 已部署，用户确认完成）

图库授权过期或缺失时，本机 HQ 页面显示「一键授权」。仅主动点击会调用新接口 `POST /api/hq/authorization/renew`（空 JSON 请求），页面加载、刷新、轮询不续期、不打开登录页面，也不自动生成。成功后自动刷新人物图库，保留已选服装、姿势、人物和参数；「只选本机档案」不需要这个按钮。

后端复用 `E:/Dream/tools/hq-depth-r2/node_modules/wrangler/wrangler-dist/cli.js` 与 PATH 中的 Node.js。账号由 `config/dream/hq-authorization.jsonc` 固定为既有 HQ 所属账号，不接受浏览器传入账号、路径、命令、凭据或回调 URL。前提是当前 Windows 用户已在本机 Wrangler 登录且有该私有 R2 桶的写权限；ChatGPT 的 Cloudflare 连接器登录不会自动等同于本机 CLI 登录。本次没有触发真实登录或验证当前 OAuth 状态。

流程为：生成 32 字节随机 token → 私有临时文件保存 → 用既有登录通过 Wrangler 将 `{version:1,expiresAt:毫秒时间戳}` 写入固定私有桶的 `sessions/v1/<SHA256(token)>` → 用新 token 实际读取既有 `/api/person/list?limit=1` 验证 → 原子替换本机会话文件 → 清除授权/人物列表缓存。新会话有效期 1 小时；重复点击和丢失响应后的重试会复用仍有至少 5 分钟有效期、且经接口验证的会话。原始 token 从不进入 CLI 参数；CLI 不收到原始 token。ACL 在写入凭据前设定，临时目录和日志随操作结束清理。

Cloudflare 登录失效返回 `HQ_CLOUDFLARE_LOGIN_REQUIRED`；网络或 R2 权限失败返回 `HQ_AUTH_RENEW_FAILED`；45 秒 CLI 超时返回 `HQ_AUTH_TIMEOUT`；同一时刻的重复请求返回 `HQ_AUTH_BUSY`。失败不覆盖旧会话，不对外回显 CLI 原始诊断。不修改 Worker、插件工具协议、白模图库或深度图映射。Wrangler 命令依据[官方 R2 文档](https://developers.cloudflare.com/workers/wrangler/commands/r2/)及本机 4.156.0 源码核对。

验证记录：`docs/dream-windows/HQ_AUTHORIZATION_ACCEPTANCE.md`。前后端已部署为 `dream-hq-one-click-authorization-20261104`，服务、授权能力和静态资源读回通过；用户自行确认完成。独立构建及回滚文件位于 `E:/Dream/test-runs/hq-authorization-20261104/deploy`。自动流程没有代用户签发真实授权或生图。回滚仅恢复前后端代码；保留现有会话、人物档案、作品和任务目录。

选择图库照片时，下载人物原图需要有效的私有会话；授权过期后需重新签发。成功下载并校验的输入可在本机执行，不依赖十分钟单图 grant 排队存活。只选本机档案时不读取私有人物图库。不能用缩略图、截图或原素材外站替代失败的 R2 原图。

## 接口与证据

新增接口均在本机 `/api/hq`：`status`、`catalog`、`asset`、`jobs`、单任务状态、`cancel`、三角色 `inputs` 和 `result`。Cloudflare 原有 MCP 三个工具不承担本机执行。

`POST /api/hq/jobs` 只接受一种人物来源：选择图库照片传 `personId`，选择本机档案传 `profileId`。两者同时提供或均未提供时返回 HTTP 422，不创建任务。`GET /api/hq/status?personSource=profile` 不检查私有人物图库的会话；任务中的 `personSource` 和人物输入记录注明实际来源。

2026-11-02 已在本机浏览器分别用档案和图库 JPEG 提交同服装、同姿势、同种子的两次生成。档案模式刷新和提交期间没有人物图库请求，任务的人物输入与建档参考 PNG 逐字节一致；图库模式的人物输入与所选 JPEG 的 SHA-256 一致。两张 768×1152 成片均已从任务页下载并校验哈希，三路条件各参与了 30 步采样。

本机任务使用持久幂等键。网络重试和重复点击复用同一创作动作；参数变化或明确点击失败／取消任务的“按相同设置新建重试”才创建新动作。手动重试保留旧任务，生成新的请求编号。重启中断不能自动重跑，失败也不能被接口成功回执掩盖。

每次记录三图角色、原始 ID、SHA-256、尺寸，预处理与条件对应关系，实际模型文件、参数、种子，送入模型的条件绑定、阶段耗时与成片 SHA-256。人物、姿势和服装必须使用独立输入。人物原图、作品、精修版本及含私人图像的验收文件均不进入 Git。

启用完整深度库时，先停止空闲服务并运行 `scripts/enable_hq_paired_depth.ps1` 核验模型。在项目目录运行以下命令，使用本机已有的 Wrangler 授权从自有 R2 获取并校验完整包。

```powershell
npm.cmd install --prefix E:/Dream/tools/hq-depth-r2 --save-exact wrangler@4.156.0
python scripts/install_hq_depth_library.py --activate
```

传入 `--bundle <已回读的 bundle.zip>` 可离线安装。传入 `--index-only` 可只安装索引，在首次生成时按需补齐缓存。发布记录与 SHA-256 随 Dream 代码保存在 `config/dream/hq-paired-depth-v1/full-release.json`。深度图独立存放在 `hq-tryon-assets/dream-depth/v1/`，本机缓存位于 `E:/Dream/models/hq/depth-library/`。配置有变动时安装器会输出备份路径。构建前端并启动服务后，`/release.json` 显示 `dream-hq-person-source-20261102`。

原 HQ 选材器与 MCP 的 `get_tryon_asset({kind:"pose",id})` 继续读取白模 PNG。深度选择、补取和使用回执仅在 Dream 本机生成流程内执行。

## 排障和回滚

- 服务离线：使用原启动器；先核对端口监听归属，不停止其他项目服务。
- 人物授权失效：点击「一键授权」，成功后自动刷新。若提示本机 Cloudflare 登录失效，需先在本机完成 Wrangler 登录；按钮不会绕过账号授权。公开素材不需要人物会话。
- 原图校验失败：保留错误和已下载证据，不改用缩略图。已终止任务需明确创建新动作，不能隐式再推理。
- 保存的姿势可直接复用。模型文件缺失时页面会提示对应姿势的模型状态。骨架提取失败时可在任务详情查看原因，遮挡和多人图可能不适合现有单人骨架模型。
- 显存不足：终止当前任务并确认 CUDA 工作进程退出；不自动同时启动第二个生成或无限重试。
- 修脸／精修效果不满意：查看原图，按原有工作台保留版本、选择版本；不覆盖参考照或原始作品。
- 清晰增强不可用：检查人物配置中的模型路径及其工作解释器；增强失败不会把原图作为成功结果发布，也不会自动覆盖当前选择。增强成片不可重复放大；需要改脸或光照时先选择原图或增强前版本。
- 回滚时先停止空闲服务，将启用脚本保存的备份恢复到 `E:/Dream/data/hq/pipeline.json`，再使用上一个版本的后端与前端启动服务。原有作品和人物档案沿用现有存储。

验收必须分别记录：软件测试、实际三图绑定、可查看下载成片、人物外观、服装特征、姿势与全身构图。上述接口或文件存在本身不是视觉 PASS。
