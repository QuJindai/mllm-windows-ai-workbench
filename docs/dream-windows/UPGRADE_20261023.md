# Browser workstation upgrade — 2026-10-23

## Delivery scope and important exception

This is the existing local browser workstation, not a replacement EXE. The
upgrade implements operations diagnostics, resumable batches, bounded cross-batch
model reuse, visual-reference sampling windows and real visual-route H6/H7.

**Illustrious XL + Plus Face has NOT passed image-quality acceptance.** Its
implementation is experimental and disabled by default. In controlled local
tests the base model rendered a coherent character with reference strength zero,
but reference injection at 0.25 degraded colour/line quality and 0.8 destroyed
structure. Changing the sampling window did not establish an acceptable quality
baseline. Earlier local comparisons also exhibited this failure, before the warm
worker existed. Do not describe this route as a completed quality upgrade. The
existing Cyber visual-reference and Illustrious FaceID routes are separate.

No existing profile, preset or reference photo is rewritten to conceal this
failure. `complete` means output publication, not aesthetic or likeness approval.

## Operational behaviour

- `GET /api/operations`: real release, disk capacity, installation checks and
  bounded persisted pending-record counts. Unknown is distinct from zero.
- Below 10 GiB: warning. Below 2 GiB: reject new generation. History viewing,
  cancellation and readback of an already accepted retry remain available.
- Nothing is automatically deleted or downloaded. Diagnostics do not prove GPU
  or model quality merely because files exist.
- `scripts/diagnose_dream_web.ps1` provides local diagnostics. Continue using
  `scripts/start_dream_web_background.ps1` and `http://127.0.0.1:8766/`.

## Batch recovery

Retry failed / continue unfinished creates a child batch using the original
frozen per-item parameters, seeds and original item indices. Completed originals
are unchanged. A parent-scoped durable request key prevents retries after a lost
response from silently creating another child; once acknowledged, recovery reads
the child instead of POSTing again. Retry the child if that child later fails.

Preparation time is included in new batch elapsed times, including a worker that
never emits progress. Terminal elapsed time is persisted and does not grow while
reading history. Old inaccurate timestamps are not invented or retroactively
overwritten.

## Worker lifecycle

`persistentWorker: true` in the local identity runtime enables one bounded owned
worker. The example remains opt-in. Compatibility checks include model/reference
bytes and fixed request controls. Changed assets/settings start a fresh process;
uncertain execution failures are not automatically replayed. Idle expiry is at
most 60 seconds / 32 batches per process. Cancel, shutdown and ordinary native
generation enforce an exit barrier before reusing CUDA.

Real Windows validation exposed a stdin descriptor-lock deadlock during native
imports. The worker now reads one frame, joins that reader, and only then imports
or runs inference; it does not block reading the next frame while rendering.

Before sending the first batch, the parent verifies the actual worker PID,
creation time, process ancestry and Job Object membership. Release waits for both
zero active Job processes and signalled owned process handles. A failed terminate,
query, wait or handle-close retains ownership and blocks native inference. Real
Win32 CPU process-tree tests exercise this boundary; final GPU cancellation and
native hand-off under this last revision still require an uncontended GPU check.

Keep cold-load, compatibility-file verification, sampling and research overhead
separate when interpreting timings. Memory residency is bounded, not zero-cost.

The initial Cyber 768×768 / 30-step pair took 177.234 s cold and 208.453 s warm;
`sessionReused` was true for the latter. This **does not establish acceleration**.
Other workload was present; a subsequent read-only GPU inventory confirmed
Blender using 100% GPU while no Dream inference process remained. No unrelated
process was terminated. Repeat a fair cold/warm benchmark when the GPU is idle;
do not infer phone-parity or a stable throughput improvement from this run.

## Research interpretation

- H6 visual reference: at the same latent, timestep and text, run an extra
  prediction with reference injection disabled. This is not a face-match score.
- H7: measured Q/K, FP32 probability recomputation, representative layers/steps,
  head averages and fixed spatial anchors. Cross attention represents conditional
  **text**, not reference-image token attribution.
- One local 512×512 / 8-step run produced 5 H6 steps, 135 self-attention maps and
  480 text cross-attention maps. All 135 self maps passed validation; probability
  sums were 0.999999945–1.000000100. Total trace assets were 11,192,538 bytes.
- These maps were opened in the real browser. Artifact validity is independent
  of the failed Illustrious image-quality result.
- Retrieval failure and unknown capture settings are no longer mislabeled as
  “capture was disabled”. No placeholder heatmap is substituted.

## Reproducible acceptance and privacy

`scripts/verify_identity_upgrade.py` runs explicitly requested local comparison
cases from an approved existing batch. It creates new outputs, never updates a
profile, and refuses to put private receipts inside the public repository. Use a
new output directory. Cases include cold/warm, scheduled, research and bounded
reference-strength comparisons. It records facts; images must still be viewed.

Private test images, embeddings, references and historical receipts stay local.
The public release contains source, synthetic tests, generic config examples and
this redacted report. Protected profile files were independently SHA-256 checked
after acceptance and remained unchanged.
