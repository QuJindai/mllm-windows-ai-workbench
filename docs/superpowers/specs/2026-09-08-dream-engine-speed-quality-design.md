# Dream Windows 生图引擎速度与质量升级设计

## 目标

在不牺牲真实生成质量、不增加 Codex 与浏览器崩溃风险的前提下，缩短 Dream Windows 浏览器版的首张图等待时间，并纠正当前模型身份、默认生成参数和运行时元数据中的错误。升级后的系统只在浏览器运行，模型、缓存、输出、日志和构建资产继续位于 `E:\\Dream`。

## 已确认的问题

1. 当前注册表把标准版 `CyberRealistic XL v10` 错标成 `DMD2`。8 步 DMD2 参数因此被用于标准模型，结果会出现过饱和、轮廓崩坏和细节不足。
2. 普通生成默认开启 H6 trace。H6 会持续写入 latent 和遥测文件，适合分析，不适合作为每次生成的默认模式。
3. Windows 包装脚本每次任务结束后都重新计算约 4.18 GB GGUF 文件的 SHA-256，单次固定增加约 6 秒。
4. CUDA 引擎支持 diffusion Flash Attention，但包装脚本没有启用；受控测试显示可缩短采样时间。
5. 当前网页默认使用 832 x 1216、20 步、CFG 7；这既不是标准 v10 的合理质量参数，也不适合 6 GB 显存上的快速默认体验。
6. 每个任务仍创建一个新的 `sd-cli` 进程，模型上下文无法跨任务复用。这个问题需要后续持久化 worker/server 改造，但不阻塞本轮低风险优化。

## 设计决策

### 1. 模型身份以实际文件为准

- 模型 canonical id 改为 `cyberrealistic-xl-v10-standard`。
- 显示名称改为 `CyberRealistic XL v10（标准版）`。
- `dmd2.enabled` 固定为 `false`，直到本机实际安装并校验真正的 DMD2 模型文件。
- 保留 `cyberrealistic-v10-dmd2` 作为兼容别名，旧历史记录和旧请求仍能解析，但新任务统一写 canonical id。
- 模型列表只显示一个真实模型，不通过复制条目制造虚假能力。

### 2. 默认生成采用安全平衡档

普通生成默认值调整为：

- 512 x 512
- 20 steps
- CFG 4.0
- DPM++ 2M SDE / Karras
- trace level `basic`

这是 6 GB 显存上的启动档，不限制用户切换到更高分辨率或 H6/H7。H6/H7 继续保留，但必须由用户主动选择，并清楚显示其额外耗时。

### 3. Flash Attention 默认启用

- CUDA 生成参数默认加入 `--diffusion-fa`。
- 提供环境变量 `DREAM_DISABLE_DIFFUSION_FA=1` 作为兼容性回退。
- 不提高 GPU 功耗上限。当前 1024 x 1024 已接近显存上限，提高功耗不能解决固定开销，还可能增加桌面应用不稳定性。

### 4. 模型哈希使用文件身份缓存

- 新增 PowerShell 支持模块，以模型绝对路径、文件大小和 UTC 修改时间作为缓存身份。
- 缓存命中时直接复用 SHA-256；文件大小或修改时间变化后强制重新计算。
- 缓存文件位于 `E:\\Dream\\cache\\model-hashes.json`。
- 写缓存采用临时文件加原子替换，避免进程中断留下半个 JSON 文件。
- 元数据记录本次是否命中缓存，以便诊断。

### 5. 运行元数据拆分真实耗时

每个任务的元数据增加：

- `engine_wall_time_ms`
- `postprocess_time_ms`
- `flash_attention`
- `model_hash_cache_hit`

页面和日志可据此区分采样慢、解码慢、进程启动慢和后处理慢，避免把所有时间都归咎于 CUDA。

## 兼容性与错误处理

- 旧模型 id 在 HTTP runtime 入口完成别名解析，进入 job runner 前转换为 canonical id。
- 不支持的 sampler 继续返回结构化校验错误。
- 哈希缓存损坏时忽略旧缓存并重新计算，不让生成失败。
- Flash Attention 启动失败时不会自动吞错；用户可以通过明确的环境变量回退，日志保留实际参数。
- 所有性能结果均来自真实引擎输出，显微镜继续区分 `observed`、`derived` 和 `unavailable`。

## 验收标准

1. 注册表、后端模型接口和网页都不再把当前模型显示为 DMD2。
2. 旧 id 请求仍能生成，任务元数据保存 canonical id。
3. 普通生成默认 trace 为 basic，H6/H7 仍可手动选择。
4. 包装脚本默认包含 `--diffusion-fa`，回退变量能够移除该参数。
5. 同一模型连续运行时第二次哈希为缓存命中；模型文件身份变化后缓存失效。
6. 前端 Vitest、后端 pytest、core pytest 和生产构建全部通过。
7. 至少完成一张真实 512 x 512 平衡档图片，并人工检查内容可辨识、色彩和结构没有此前 8 步误配造成的明显劣化。
8. 记录优化后端到端耗时、引擎耗时和后处理耗时，作为持久化引擎阶段的基线。

## 后续阶段

本轮完成后再实施持久化 CUDA worker：构建并验证 `sd-server` 或等价常驻进程，让模型跨任务复用；同时增加 8766 服务守护和健康恢复。该阶段独立验收，以免把模型身份修复、参数修复与进程架构改造混在同一次故障定位中。
