# Dream 常驻 CUDA 生图引擎设计

日期：2026-09-08

## 目标

浏览器端普通生图不再为每个任务重新启动 `sd-cli.exe` 和加载模型。后端复用绑定在 `127.0.0.1` 的 `sd-server.exe`，降低首张之后的生成延迟，同时保持当前输出、历史记录和显微镜契约。

## 已测基线

- 当前浏览器 512×512、20 步、标准模型：约 13.7 秒。
- 常驻服务首次同参数：约 15.0 秒。
- 常驻服务热运行同参数：约 9.0 秒。
- 常驻服务热运行 1024×1024、20 步：约 37.0 秒。
- 常驻服务热运行 768×768、20 步：原生日志实测约 19.4 秒，肉眼细节显著优于 512。

因此首要升级是复用模型，而不是通过降低分辨率或步数伪造速度提升。
默认平衡档采用 768×768、20 步；512×512 仍可手动选择为快速预览。

## 路由策略

- `traceLevel=off/basic`：优先常驻 `sd-server.exe`。
- `traceLevel=h6/h7`：继续走 `dream-core -> sd-cli`，因为该链路负责导出真实 latent 投影、通道统计和 H7 数据。
- 单元测试注入了 `command_runner` 时：保持既有命令行路径，避免测试意外启动真实 GPU 服务。
- 常驻服务不可用、启动失败或端口被不匹配的进程占用：在提交原生服务任务前回退现有 CLI 链路。
- 常驻服务已接受任务后若失败：直接报告失败，不自动重复生成，避免重复占用 GPU 和产生非确定性结果。

## 生命周期和安全

- 默认服务地址 `http://127.0.0.1:12444`，只监听本机。
- 首次普通生成时惰性启动，之后跨浏览器任务复用。
- 若端口已有健康的 `sd-server`，只有其 capabilities 返回的模型路径与注册表模型一致时才复用。
- 不终止来源不明或模型不匹配的进程；这种情况直接回退 CLI。
- 进程使用无窗口模式，日志写入 `E:\Dream\logs\engine-server`。

## 数据真实性

- PNG 和 JSON metadata 继续落在 `E:\Dream\outputs\YYYY-MM-DD`。
- metadata 新增 `execution_mode=persistent-server`、原生服务任务 ID、Flash Attention 状态和实测总耗时。
- 常驻服务没有提供 conditioning/sampling/decode 分段耗时时，不推算或伪造分段，只在 Basic 显微镜显示一个 `Native generation` 实测节点。
- H6/H7 保持现有观测数据和文件证据。

## 取消和错误处理

- Dream 任务 ID 与原生服务任务 ID 建立映射。
- 用户取消时调用原生 `/cancel` 接口，并把 Dream 任务标记为已取消。
- HTTP 超时、无效 JSON、无图片、无效 Base64、原生任务失败均转成明确错误并保留日志。

## 验收

1. 单元测试证明 Basic/off 优先常驻、H6/H7 继续 CLI、回退与取消正确。
2. 全部前后端和核心测试通过。
3. 浏览器真实生成一张 512×512、20 步图片；metadata 显示 `persistent-server`，耗时接近热运行基准。
4. 检查输出图像尺寸、极黑/极白比例和肉眼结构质量。
5. 模型、历史、显微镜、设置页面无控制台错误。
