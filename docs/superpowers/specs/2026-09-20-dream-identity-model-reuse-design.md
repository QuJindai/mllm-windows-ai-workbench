# Dream 人物创作：原 SD1.5 模型复用与轻量身份链

日期：2026-09-20

状态：用户已同意免 ComfyUI 的人物创作方向，并在比较 Cyber 适配成本后明确选择“还是之前的模型”。首期恢复 Realistic Vision V5.1 + SD1.5 FaceID Plus V2；尚未完成新后端适配或真人效果验收。

## 1. 用户目标与范围

在现有 Dream 简体中文浏览器界面，通过人物参考照、场景提示词和可选 LoRA 生成保留人物身份的图像，并查看处理过程。用户不需要操作 ComfyUI 节点，也不需要安装新桌面 EXE。人物功能复用原 FaceID 工程的 Realistic Vision V5.1、SD1.5 FaceID Plus V2 及其配套 LoRA，减少重复下载和多阶段处理负担；Cyber 等保留现有普通生图用途，不因本设计删除或更改默认模型。

首期仅实现单人物参考、可选兼容 LoRA、身份条件生成、历史留存与参考/结果对照。个人 LoRA 训练、多人物、自动 Flux Fill、连续手部/服装修复不纳入首期。原 FaceID 工程、照片及实验资产保持原样，不自动访问其永久盲测集。

## 2. 本机核实结果

来源：`config/dream/model-registry.json` 和实际文件属性。下表是磁盘体积，不是显存峰值；本轮未重新计算大文件哈希。

| 底模 | 架构 | 现有源文件 | 当前运行文件 | 本功能定位 |
| --- | --- | --- | --- | --- |
| CyberRealistic XL v10 标准版 | SDXL | FP16 safetensors，6.46 GiB | Q8_0 GGUF，3.89 GiB | 保留普通生成；不纳入首期 FaceID 适配 |
| DreamShaper XL Lightning | SDXL Lightning | safetensors，6.46 GiB | Q8_0 GGUF，3.89 GiB | 保留普通生成；不纳入首期 FaceID 适配 |
| Animagine XL 4.0 Opt | SDXL | safetensors，6.46 GiB | Q8_0 GGUF，3.89 GiB | 保留普通生成；不纳入首期 FaceID 适配 |
| 原工程 Realistic Vision V5.1 | SD1.5 | FP16 safetensors，1.99 GiB | 不属于当前 Dream 注册模型 | 人物功能首期底模；注册为独立 SD1.5 模型，不替换普通生成默认值 |

当前模型源文件和量化文件均已存在，不需要重新下载底模。原工程拥有 SD1.5 FaceID Plus V2 及其配套 LoRA、CLIP Vision、InsightFace；这些文件的存在不代表所有格式都可被新后端直接加载。

兼容性分为四层，不能混为一谈：

1. SDXL 底模可以作为 SDXL FaceID 适配的候选，但必须使用匹配的适配器。
2. SD1.5 FaceID、ControlNet 和个人 LoRA 不能直接用于 SDXL。
3. 当前 C++ 引擎的普通 IP-Adapter/Plus 支持，不等于 FaceID Plus V2 支持。
4. Diffusers 有 GGUF 模型组件加载接口，但官方说明不支持把完整 GGUF 直接交给 Pipeline 加载；不能据此声称当前 SD.cpp SDXL GGUF 可直接复用。

## 3. 设计决定

保留 Dream 浏览器、API、任务队列和现有量化生成后端。增加独立的人物条件处理边界，参考照分析与身份特征缓存不常驻占用 GPU。FaceID/LoRA 推理必须绑定明确的后端与已验证的模型组合。

人物功能选用 Realistic Vision V5.1 + SD1.5 FaceID Plus V2 + 对应 FaceID 配套 LoRA。人物特征使用已有 InsightFace 与 CLIP Vision，必要的人脸修正作为可选独立阶段，保留修正前后的原图。个人身份 LoRA 仍是未通过视觉验收的研究资产，默认关闭，不与 FaceID 配套 LoRA 混淆。

采用独立 Diffusers 人物工作进程读取已有 SD1.5 模型，不调用 ComfyUI 服务。原 C++ 量化引擎继续承担现有普通生成；按任务路由，不改变现有模型的运行方式。旧工程模型仅只读引用，不移动或覆盖；格式转换若确有必要，单独保存到 E 盘并记录源哈希。实现前校验 checkpoint 中的 VAE 状态、编码器配置和适配器加载，不能根据文件名猜测或误用目录中的其他架构 VAE。

如人物工作进程的显存、速度或质量不满足本机要求，报告实际结果并保留为未验收状态；不静默换为 Cyber、PhotoMaker 或 ComfyUI，也不把“能出图”视为完成。

PhotoMaker 是另一种身份条件算法；即使现有引擎已有相关支持，也不得无说明替代 FaceID、宣称效果等价。

所有新增环境、模型适配器、特征缓存和日志放在 E 盘。可复用文件先确认哈希、模型架构和格式；只补齐 SD1.5 身份链缺失的必要组件，不下载 SDXL FaceID 适配器或新的大底模。模型文件大小、环境占用、显存峰值和生成耗时分别记录，不混用指标。

## 4. 组件与数据流

1. 人物资产服务：用户主动上传/选择参考照，校验图像格式和大小；无人脸明确报错，多人脸要求选定对象，不猜测。
2. 特征工作进程：对齐选定人脸，计算身份和图像特征；缓存键包括图像内容哈希、选定人脸、预处理版本和编码器哈希。照片与特征只存本机，不写入普通日志。
3. 适配清单：记录底模架构/哈希、适配器架构/哈希、LoRA 类型、后端、采样约束和验证状态。FaceID 配套 LoRA 与个人/风格 LoRA 分开显示和调节。
4. 生成任务：绑定人物资产 ID、模型 ID、适配清单 ID、LoRA 列表及参数；开始后冻结配置，跨页面保持状态。未知或不兼容组合拒绝执行。
5. 历史与过程视图：保留实际种子、模型/适配器哈希、原始输出、可选修正输出、各阶段耗时和错误。人脸修正默认不掩盖原始生成质量。

第一版无需图形节点编辑器；显示“参考照处理 → 身份条件 → 生成 → 对照”阶段卡片及真实产物即可。

## 5. 6GB 显存与故障边界

- 原生后端和人物工作进程共享 GPU 独占调度；不同时装载两套底模，不并发训练。
- 单图运行、参考特征预计算、按阶段装卸模型，VAE 分块/卸载按实测选择；不承诺仅移除 ComfyUI 就一定提速。
- 默认保留至少 1 GiB 的设备显存余量作为初始预算目标，按实测峰值核对；外部进程占用增加时拒绝启动或排队，不反复 OOM 重试。
- 不静默降低分辨率、改变模型、改成全 CPU 推理或删除用户参考图来完成任务。取消和异常退出必须释放工作进程与 GPU 租约。
- SD1.5 验证从 512×768 单图开始，与同一底模、尺寸和采样参数的无身份条件基线比较。首期不默认增加二次高清修复；256×256 等诊断输出不作为人物质量交付证据。

## 6. 显微镜边界

基础过程视图只显示实测阶段、张量形状、缓存命中、耗时和显存。不展示伪造注意力图，不把 ArcFace 分数换算成“本人相似百分比”。

现有 H6/H7 采集绑定 C++ 调试引擎，不能继承给新的 Diffusers 工作进程。新后端或新适配器的文本注意力、图像条件注意力和 self-attention 分别声明能力与实际采集状态。H6/H7 没有真实产物时显式显示未采集，基础人物功能可独立验收。

## 7. 验收门槛与推进顺序

先验证 Realistic Vision V5.1 的无身份条件基线，再验证同一模型的 FaceID Plus V2、配套 LoRA 和可选修正阶段。首期不扩展 Cyber、DreamShaper 或 Animagine 的身份生成，也不以旧 ComfyUI 的成功记录替代新后端验收。

技术验收：

- 架构/格式不匹配时有明确错误；禁用身份条件后不残留适配器或 LoRA 效果。
- 一个用户指定人物、两组固定种子、肖像与半身两类提示进行配对对照，检查身份保持、提示服从和明显形变。不得只展示最优种子。
- 同一模型、分辨率、采样设置下分别报告冷启动/热运行时间、GPU 峰值、系统内存和增量磁盘占用；不预设未经实测的秒数。
- 连续五次任务无 OOM、崩溃和重复提交；页面切换、取消、失败恢复后可继续生成，空闲显存回到可解释的基线。
- 没有 ComfyUI 进程和服务也可完成全链路。原有普通生成与历史功能无回归。

视觉验收必须查看原图并由用户确认身份效果；自动相似度指标仅辅助筛查。所有许可限制随模型登记；未获授权的非商业研究权重不得标记为可商用。

推进顺序：SD1.5 模型/适配器加载验证 → 6GB 资源与质量对照 → 接入独立人物后端及 GPU 调度 → 人物 UI 与历史 → 显微镜真实采集。没有通过资源与质量验收时，不把人物功能标记为可交付；既有普通生成默认模型保持不变。
